Architecture Decision 1 — Factory Scope

The factory consists of 16 content-production agents.

PerformanceLearningAgent is intentionally excluded from the factory.

Reason:

It consumes performance data and improves the system after content is published.

It is not part of the content creation pipeline.

Architecture Decision 2 — Canonical Output

The canonical output of the factory is not an article.

The canonical output is:

Knowledge Asset

Reason:

One approved insight may later produce:

  • Article

  • FAQ

  • Recommendation Page

  • LinkedIn Post

  • Email Teaser

  • Video Script

  • Case Study

The factory should generate reusable knowledge assets first.

Flow:

Approved Insight
↓
Knowledge Asset
↓
Channel-Specific Assets

Not:

Approved Insight
↓
Article
↓
Everything Else

Architecture Decision 3 — Approved Insight Contract

No content generation may begin without an approved insight.

Approved Insight becomes the canonical source of truth.

Schema:

Insight {
  id
  title
  rawSource
  sourceType
  // note
  // interview
  // linkedin
  // coaching-session
  // workshop
  // voice-note
  extractedInsight
  status
  // draft
  // review
  // approved
  // archived
  approvedBy
  approvedAt
  evidenceUrls[]
  targetEntities[]
  targetQueries[]
  freshnessExpiresAt
  createdAt
}

Rule:

status = approved
AND
freshnessExpiresAt > now

must be true before any content workflow starts.

Architecture Decision 4 — Runtime Dependencies

Task 025 may introduce runtime dependencies.

Allowed:

  • zod

  • langgraph

  • langchain-core

Not allowed:

  • workflow execution

  • content generation

  • provider calls

Reason:

Contracts should be built against the real runtime stack.

Task 026 will implement orchestration.

Architecture Decision 5 — Provider Layer

The system must never depend directly on a single model provider.

Introduce:

DEFAULT_RESEARCH_MODEL
DEFAULT_WRITER_MODEL

Task 025 defines the contracts.

Task 026 implements execution.

Architecture Decision 6 — Prompt Versioning

Every agent execution must be traceable.

Required metadata:

AgentRun {
  agentName
  promptVersion
  model
  startedAt
  completedAt
  status
}

Reason:

Without prompt versioning the system cannot be debugged or improved safely.

Architecture Decision 7 — Claim Taxonomy

Every generated statement must belong to a claim category.

Factual Claim

Example:

Engineering managers spend 40% of their time in meetings.

Requires evidence.

Research Claim

Example:

A Gartner study found...

Requires evidence and date.

Client Outcome Claim

Example:

Delivery improved by 40%.

Requires strongest verification.

Framework Claim

Example:

The Player Trap occurs when...

Does not require external evidence.

Requires framework ownership attribution.

Opinion Claim

Example:

Most managers are promoted too early.

Does not require external evidence.

Must be clearly framed as opinion.

Architecture Decision 8 — Claim Ledger

Task 025 defines the Claim Ledger contract.

Task 027 implements storage.

Storage decision:

Payload Collection

Reason:

Claims must remain queryable.

Future queries:

  • which pages use this claim?

  • which claim lost evidence?

  • which claim appears across the site?

require first-class storage.

Architecture Decision 9 — Recommendation Pages

Recommendation pages must never be published automatically.

Task 029 is revised:

Old:

Create recommendation pages

New:

Generate review-ready recommendation page drafts

Human approval remains mandatory.

This aligns with the governance model.
